# Arthur Zhuk — Personal Space

Arthur's personal site: an editorial homepage with case studies, an interactive particle torus, expandable career history, and **AI Arthur**, a profile-grounded chat that visitors can open from anywhere on the page.

`/` is the whole site. `/portfolio` (the old location of the editorial page) permanently redirects to `/`.

## Run locally

```sh
npm ci
npm run dev
```

Open http://localhost:3000. Development output uses `.next-dev` so a production build can run alongside the preview.

## Full application

```sh
npm run build
npm start
```

The `/api/generate` endpoint uses the server-side `OPENAI_API_KEY` environment variable. Credentials are read at request time, never exposed to the browser, and never included in this repository. If runtime credentials are missing, requests return an honest 503 with a contact alternative. See `.env.example` for every setting.

### AI chat

- Uses AI SDK 7 and the OpenAI Responses API with strict structured output.
- Defaults to `gpt-5.6-luna` for a low-latency, cost-conscious profile guide. `OPENAI_MODEL` optionally selects another Responses-compatible model that supports Structured Outputs; account access must cover that model.
- Streams validated content into app-owned response cards. Contact URLs and the résumé path are selected from an allowlist, not generated by the model.
- **Job fit:** the "Match me to a role" starter pre-fills a prompt; paste a job description and the guide answers with where Arthur matches (with evidence) and where the profile shows gaps. It is told never to invent experience.
- **Ask from the hero:** the homepage question box (and its suggestion chips) opens the chat and sends the question once.
- Keeps recent user questions and completed assistant answers in context, with a 24,000-character history budget. Cancelled or incomplete answers are excluded.
- Supports cancellation, retries, copying answers, relevant follow-ups, and 30 questions per conversation. Reset starts a fresh conversation; retries do not add duplicate questions.
- Limits input to 4,000 characters, request bodies to 180 KB, output to 4,000 tokens, and generation to 45 seconds. Uses one retry for eligible provider failures and disables storage of Responses with `store: false`.
- Conversations remain in memory in the current page. There is no conversation database.
- The chat states plainly that it is an AI guide answering from Arthur's public profile, not Arthur.

### Abuse protection and cost control

`/api/generate` is public and spends an API key, so it is rate-limited (`lib/chat/rate-limit.ts`) before the request body is read or a model is called:

| Limit | Default | Setting |
| --- | --- | --- |
| Requests per visitor per minute | 8 | `CHAT_RATE_LIMIT_PER_MINUTE` |
| Requests per visitor per day | 60 | `CHAT_RATE_LIMIT_PER_DAY` |
| Requests per day, site-wide | 1500 | `CHAT_DAILY_BUDGET` |

Blocked requests get a `429` with `Retry-After` and a plain-language message. Visitors are identified by a truncated SHA-256 of the platform-reported IP; the address itself is never stored.

Counters live in memory by default, which stops a naive loop but is **per server instance** on serverless platforms. For limits that hold everywhere, set `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` (no extra dependency; it uses Upstash's REST API). If the shared store is unreachable the limiter falls back to the in-memory counter rather than switching off.

Also set a hard monthly spend limit on the OpenAI key in the OpenAI dashboard; that is outside what this repository can enforce.

### Validation

```sh
npm test
npm run build
# In a separate terminal:
npm run dev -- --port 3002
npm run test:browser
```

Tests use a mock language model and never call OpenAI. The browser tests intercept every `/api/generate` request and exercise the real SDK protocol, the hero question flow, the job-fit starter, the `/portfolio` redirect, and the mobile layout. Set `CHAT_TEST_URL` to test another local server and `PLAYWRIGHT_CHROMIUM_EXECUTABLE` if needed. Live model quality and account access require a separate check in the configured environment.

API references: [OpenAI Responses migration](https://developers.openai.com/api/docs/guides/migrate-to-responses), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), and [AI SDK custom data streaming](https://ai-sdk.dev/docs/ai-sdk-ui/streaming-data).

## Editing content

| To change | Edit |
| --- | --- |
| Roles, skills, contact links, headline stats, case studies (also what the AI knows) | `lib/profile-data.ts` |
| Hero suggestion chips, "how this site works" copy, interest cards | `lib/site-content.ts` |
| Add a "Book a call" link everywhere | set `NEXT_PUBLIC_BOOKING_URL` |
| Real photos on the interest cards | put images in `public/interests/` and set `image: { src, alt }` on a card in `lib/site-content.ts` |

The case studies restate figures that already appear in the role list. Add first-person detail (what you decided, what went wrong, what you would do differently) in `lib/profile-data.ts` to make them stronger; the AI will use it too.

Styles: `app/globals.css` (tokens and chat components), `app/portfolio.css` (the page), `app/chat.css` (the dialog and the chat inside it). The particle illustration respects reduced motion and pauses rendering when offscreen or in a hidden tab. One shared audio player (`lib/audio-manager.ts`) drives both the page's soundtrack control and the chat's visualizer, and the file is not requested until someone presses play.

Sharing and search: `app/opengraph-image.tsx` (link-preview card), `app/icon.svg` and `app/icon.tsx` (favicon), `app/robots.ts`, `app/sitemap.ts`, and `Person` JSON-LD in `app/page.tsx`.

## Private design preview

```sh
npm run build:preview
```

This packages the production build's pre-rendered homepage and public assets into `out/`, including the share image, `robots.txt`, and `sitemap.xml`. The hosted design preview is static and intentionally disables AI requests, even if a key is present locally. To host functioning AI chat, deploy the full Next.js application with its API route and configure its secret; the static preview cannot run that route. Run a normal `npm run build` afterwards before `npm start`, because the preview build bakes in the disabled-chat setting.
